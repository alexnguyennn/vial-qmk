** Build commands
- =nix-shell= will bring up a shell with all qmk dependencies
- ~make svalboard/trackball/pmw3389/left:alex~
- ~make svalboard/trackball/pmw3389/right:alex~
- [[https://docs.google.com/presentation/d/1GnWTA1rkspQECpYGpojspFwLH1Yve-2vgQR3afrVYJo/edit#slide=id.g303b5c10ad0_0_0][flashing firmware]]
- flash board with uf2 files that are generated
  - Svalboard uses an RP2040 microcontroller which lets you flash firmware by drag-and-drop to an onboard flash drive.  After loading, it immediately reboots and comes up as a Svalboard, and the flash drive disappears.
Double-tap the RESET button on the bottom of the case to enter bootloader mode.  An “RPI-RP2” flash drive will show up.
You’ll need to flash both sides when updating FW. To do this, each side will need to have its Master port connected to the host PC, in turn.

** Custom keys in vial
- [[https://github.com/svalboard/vial-qmk/blob/vial/keyboards/svalboard/docs/custom_firmware.md#accessing-svalboard-specific-keycodes][svalboard docs]] pointing to use =SV_SAFE_RANGE= only make sense if you don't want to make the key available to bind in Vial/keybard (given the current format of =keymap_support.h=)
  - for some reason =KC_NORMAL_HOLD/KC_FUNC_HOLD= aren't actually declared in vial.json so we can actually bind from =SAFE_RANGE=
- if you do want them bindable in Vial/keybard, you'll need to make sure it's indexed from =QK_KB_0= (see [[https://get.vial.today/docs/custom_keycode.html][vial docs]])
- can't declare a macro to be a custom key alias (e.g. =#define KEY LCTL_T(KC_0)= and then alias =KEY=)
